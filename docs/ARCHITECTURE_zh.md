# 系统架构与代码实现

## 硬件层

系统配置PG2L50H与RK3568复合板、PGL50H发送板以及双目和USB摄像头。物理四路模式中，发送板通过SFP向接收板传输后向图像，接收板汇合本地图像后通过PCIe送入RK；左右USB图像由RK采集。单板决策模式使用本地双目，不依赖SFP发送端。

## 感知层

RK3568运行YOLOv8n 11类检测与R15车道线分割。检测输入为640×640；R15前视输入为256×448。物理四路与CARLA四宫格先合成为一路检测输入，前视区域单独执行分割。该方案以共享算力覆盖多视角，单路小目标分辨率受四宫格缩放影响。

采集、检测、分割、绘制与编码分别组织；两个模型共享NPU访问锁，CPU预后处理可交叠。实时模式优先使用最新帧，离线模式按原帧序处理。绘制在图像副本上进行，模型输入保持未叠加状态。

## 交互与反馈层

- **静止决策**：左目感知、后台双目匹配与道路规则摘要传到PC，形成车辆灯光、前轮和报警反馈。
- **物理四路**：RK完成感知叠加与JPEG发布，PC负责解码和显示。
- **CARLA导航**：座舱通过串口提供导航消息；PC执行路线与车辆控制；RK的目标检测参与行人关联和AEB条件判断。
- **离线分析**：读取本地视频，输出MP4与JSON摘要，不参与实时车辆控制。

## 代码职责

|目录|主要实现|
|---|---|
|`hardware`|RTL、IP、约束、PDS工程和三份位流|
|`software/rk3568/video_input`|PCIe/USB/网络输入、颜色处理和编码|
|`software/rk3568/object_detection`|RKNN接口、DFL解码、类别策略与NMS|
|`software/rk3568/lane_detection`|R15输入转换、掩膜与绘制|
|`software/rk3568/fusion`|实时/离线主流水线、摘要、规则和测距关联|
|`software/rk3568/communication`|状态服务、OIB/AEB消息与PCIe驱动|
|`software/pc`|总控界面、CARLA场景、串口与网络通信|
|`software/raspberry_pi`|Android导航与挡位联动接口|
|`training`|YOLO与R15训练、数据适配和转换代码|

`configs/layouts`将分类源码映射到各模式所需的相对目录。启动器在`.runtime`生成运行布局，使已有模块按其接口协作；运行布局与源码目录分离，结果统一写入`results`。第三方代码和历史来源文档保留在相应来源目录。
